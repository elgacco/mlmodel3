# Прогноз недельного спроса на товары

Учебный ML-проект: прогнозирование количества единиц каждого товара, которое будет продано на следующей неделе. Прогноз можно использовать для планирования закупок и управления запасами.

## Бизнес-задача

Интернет-магазин сувениров и товаров для дома хочет заранее понимать, сколько единиц каждого товара понадобится на следующей неделе. Это позволяет:
- вовремя пополнять запасы по ходовым товарам,
- не замораживать деньги в товарах с низким спросом,
- готовиться к сезонным пикам (например, рождественскому).

Задача сформулирована как регрессия: для каждой пары **(товар, неделя)** предсказать суммарное количество проданных единиц.

## Данные

- **Источник:** [Online Retail Dataset](https://docs.google.com/spreadsheets/d/1OhYXM7MP6i6fMFEc_cl01AHvWiUkZcQQ/edit?usp=sharing) — транзакции интернет-магазина за декабрь 2010 – декабрь 2011.
- **Размер:** 541 909 строк, 8 колонок (номер заказа, код товара, описание, количество, дата, цена, ID покупателя, страна).
- **Период:** ровно один годовой сезон, что позволяет уловить сезонность, но ограничивает модель одним циклом.

## Очистка данных

Из исходных данных удалены:
- отменённые заказы (`InvoiceNo`, начинающиеся с `C`),
- строки с `Quantity <= 0` (возвраты, корректировки, списания),
- строки с `UnitPrice <= 0` (служебные операции, бесплатные образцы),
- полные дубликаты,
- служебные позиции: `POST`, `DOT`, `M`, `BANK CHARGES`, `AMAZONFEE`, `PADS`, `gift_*` (подарочные сертификаты) и др.

**Итог:** 524 878 строк, 3 907 уникальных товаров, 19 773 заказа, 38 стран.

## EDA — ключевые выводы

- **Распределения скошены вправо.** Медиана `Quantity` = 4, 99-й перцентиль = 100, максимум = 80 995. Аналогично по `UnitPrice`: медиана 2.08, 99-й перцентиль 16.98, максимум 13 541.
- **Основная масса** — розничные покупки 1–11 единиц. Редкие крупные заказы (12, 24, 48, 60) — это опт кратно упаковкам, их нельзя удалять.
- **Сезонность.** Продажи растут с сентября по ноябрь, пик — ноябрь. Минимум — февраль. Это классический паттерн магазина подарков.
- **Выручка растёт быстрее количества.** К концу года выручка увеличивается в 2.5–3 раза, а количество — плавнее. Значит, растёт средний чек.
- **Магазин не работает по субботам.** Заказов в субботу нет вообще.
- **Пик активности** — четверг, за ним вторник. Самый слабый день — воскресенье.
- **UK доминирует** — 88% всех продаж. Поэтому `Country` не используется в v1 модели.

## Подготовка данных

1. Отобраны **288 товаров**, которые продавались в каждой из 53 недель года. Это отсеивает товары с разовыми оптовыми заказами и оставляет стабильный спрос.
2. Агрегация до уровня **StockCode + неделя**: суммарное количество проданных единиц.
3. Полная сетка «товар × неделя» (15 264 строки, пропусков нет).
4. Признаки:
   - лаги 1, 2, 4, 8 недель,
   - скользящие средние за 4 и 8 недель,
   - максимум за 4 недели,
   - номер недели, месяц, квартал,
   - количество недель с начала наблюдений,
   - `StockCode` как категориальный признак.
5. Разделение по времени:
   - **train:** до 1 сентября 2011 (10 944 строки),
   - **valid:** сентябрь–октябрь (2 592 строки),
   - **test:** ноябрь–декабрь (1 728 строк).

## Модели и результаты

**Бейзлайны:**
- Baseline 1: прогноз = продажи прошлой недели (`lag_1`).
- Baseline 2: прогноз = среднее за 4 предыдущие недели (`roll_mean_4`).

**CatBoost:** `loss_function='MAE'`, `depth=8`, `learning_rate=0.02`, ранняя остановка на valid.

### Метрики

| Модель | MAE | RMSE | WAPE, % |
|---|---|---|---|
| Baseline 1 (lag_1) | 94.52 | 202.74 | 71.74 |
| Baseline 2 (roll_mean_4) | 78.95 | 167.69 | 59.93 |
| **CatBoost (valid)** | **69.70** | **163.91** | **52.91** |
| CatBoost (test) | 82.75 | 226.76 | 53.66 |

CatBoost бьёт оба бейзлайна на всех метриках. WAPE на test практически не отличается от valid — модель устойчива к новым данным, несмотря на то что тестовый период приходится на сезонный пик.

### Важность признаков

Топ-5: `roll_mean_8`, `StockCode`, `roll_mean_4`, `lag_1`, `lag_2`.

Модель опирается на сглаженный тренд товара и его индивидуальный уровень спроса, а не на отдельные выбросы. Календарные признаки дают небольшой вклад, потому что в данных всего один годовой сезон.
